# 广告接入与触发规则

## 接入范围

使用用户提供的 8 个插屏位、7 个 Banner 位、5 个激励视频位。三类广告独立洗牌轮换，避免连续选择上一广告位 ID。不同 ID 仍可能收到相同素材。

- 首页 Banner 在标题栏下方；聚会页 Banner 在“聚会小游戏”标题上方。
- 真心话大冒险：换题按钮、上滑换题共用入口，等待广告时不消耗下一题。切换真心话/大冒险分类不计操作。
- 转盘、硬币：点击转动或抛掷时判断，关闭或广告失败后才抽取结果、启动动画。
- 传气球、数字炸弹、鲨鱼牙齿：开始与“再玩一局”共用一次判断，等待时不启动本局。
- 黑8、斯诺克：整场结束后点击重新开局，使用同一随机与兜底规则；中途重置不触发。
- 数字工具、多指选人不设插屏入口。

## 插屏只使用30%概率与25次兜底

配置源：`miniprogram/data/ad-config.js`。

1. 每次打开小程序，所有插屏入口共用本次操作计数。前 2 次有效操作不触发，从第 3 次起每次按 30% 判断。
2. 另有共用的未成功展示计数。自打开或上次成功展示以来，累计到第 25 次有效操作时，无论随机结果如何，都尝试展示一次。
3. 成功展示才清零兜底计数；本次打开的总操作计数不清零，因此后续操作仍按 30% 判断，不重新保护前 2 次。
4. 失败、超时、平台频控不清零兜底；本次直接继续操作，不自动连续换 ID 重试。兜底已满时，下次有效操作再次尝试。
5. 去除所有旧的本地频率限制：5 分钟间隔、单广告位冷却、每次启动 2 次、每天 3 次、激励后等待 10 分钟、失败后等待时间或额外操作次数，均不再作为展示条件。历史缓存的展示次数和时间也不再拦截。
6. 页面切换不重置共用计数。App 初始化、从后台重新打开时重新计数；原生广告尚在加载或播放时的前台事件不会重置。

“有效操作”是通过页面状态检查的换题、转动、抛掷、开始等操作。动画中连点、等待广告时连点、无效输入等不重复计数。

兜底保证本地发起一次尝试，不保证微信实际下发广告。平台仍可能拒绝展示，例如 2002 表示距离上次插屏或激励视频间隔不足，2003 表示已有全屏广告播放；代码记录错误后结束当前尝试，不绕过平台限制。[腾讯广告官方说明](https://training.tencentads.com/uploads/202406/EPLBpxYt_5dDA71.pdf)

保留基本生命周期保护：不同时展示两条全屏广告，离开页面后不执行旧回调，加载最多等待 4 秒。这些不属于本地频率限制。

## 激励保存

编辑转盘校验通过后，每次保存按 30% 概率触发激励视频。未命中直接保存；命中则只有 `onClose` 回调的 `isEnded === true` 才保存。提前关闭、加载/展示失败或超时保留编辑内容，不保存、不返回。

- 保存按钮明确提示“保存（可能需看视频）”。
- 保存不计入插屏的操作计数或兜底计数。
- 连点不重复请求；观看前固定待保存草稿，继续保留权重、颜色、排除字段及 saved 回传。
- 看完视频后若本地写入失败，同一份草稿重试不需再看视频；修改后重新按概率判断。
- 页面离开后迟到回调不保存旧草稿，不启动旧动画。

## 排查日志

以 `[ads]` 开头：

- `interstitial-decision`：入口、共用未展示次数、本次打开总次数、触发/跳过原因。
- `min-actions`：本次打开尚未到第 3 次。
- `random-miss` / `random-hit`：30% 概率未命中 / 命中。
- `pity-hit`：达到 25 次兜底。
- `unsupported-api` / `fullscreen-busy`：环境不支持 / 已有全屏广告。
- `interstitial-attempt`：实际创建广告，含广告位 ID、入口及是否兜底。
- `interstitial-show`：SDK 报告成功展示，重置兜底；展示次数仅作为诊断统计，不限制后续展示。
- `interstitial-error` / `interstitial-load-timeout`：SDK 错误码 / 加载超时，保留兜底。

Banner 的 load 只表示加载，不当作真实曝光或收入。真实曝光与收入以流量主后台为准。
