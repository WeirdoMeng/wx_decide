## 代码路径与权益规则

- `miniprogram/utils/account.js`：登录直接使用云开发 getWXContext 注入的可信微信身份；支付时才使用 wx.login 单次 code 交换 session_key；不采集头像、昵称、手机号。账户与权益仅保存在内存，不能修改本地存储伪造会员。
- `miniprogram/pages/login/`：首次点击“微信登录并继续”；确认过后，下次打开自动登录。此按钮是应用的登录确认，不声称它会弹出微信头像授权框。分享/扫码直达由 App 导向登录后回跳。
- `miniprogram/pages/mine/`：一次付费入口、恢复购买、购买说明和客服。未完成云端配置时支付入口不可用。联系客服依赖后台已配置客服接待。
- `cloudfunctions/membership/`：code2Session、服务端签名、真实查单、交易内发货/退款、通知及定时补偿。
- `miniprogram/utils/ads.js`：统一免除 Banner、插屏和保存激励；保存直接执行原保存逻辑。非会员保持“每次打开第 3 次起，20% 插屏概率，共用 25 次操作兜底”，无新增时间/每日/启动次数限制。
- `member_grants` 文档 ID 为平台 wx_order_id 的 SHA256；同一平台订单只对应一份权益。退款先落回收标记，迟到的已支付响应不能重新开通。
- 所有签名直接对发送的同一字符串计算；客户端既不持有 AppKey，也不持有 session_key。
- 以服务端微信查单为准；客户端 success 不能发货。推送与查单均通过同一事务逻辑。查询确认支付后、向微信确认发货失败时，保留补偿记录。
- 恢复购买检查当前账户最近 5 张订单；常驻权益由服务端账户记录保留。用户转盘和设置仍是设备本地数据，不包含云同步。

## SkillHub Skill 复核与无收银台故障修正

按用户要求从 SkillHub 安装 `@tencent-adm/miniprogram-virtualpay-person` **1.0.2**，位置：`/Users/apple/.codex/skills/@tencent-adm/miniprogram-virtualpay-person/SKILL.md`。已阅读全文对照现有代码。SkillHub CLI 为 2026.8.5，仅安装 CLI 和指定 Skill，没有将其设为全局优先源。

用户已确认：**登录成功；购买没有出现微信付款界面**。目前故障日志为 `action=query, code=WECHAT_UNAVAILABLE`，它是查单阶段错误，不能直接推断原生支付 API 的失败原因。

### 确认的问题及修正

1. **HTTP 请求长度缺失，导致微信网关 HTTP 412**：Node HTTPS 原 POST 请求未发送 Content-Length，默认 chunked。使用无效诊断 AppID/Secret（不使用真实凭证、无扣款）访问 stable_token：缺少长度时为 HTTP 412 空响应；同样请求补齐长度后 HTTP 200，返回正常 JSON `errcode=40013`（测试 AppID 无效，预期结果）。修复后的真实 provider 也得到 WECHAT_40013，而非笼统的 WECHAT_UNAVAILABLE。所有 POST 现在按同一签名原始请求体计算 UTF-8 字节长度。
2. **原生支付错误码被覆盖**：支付 API fail 原来转换为通用提示，后续查单错误使定位困难。现保留原生错误码及 `client-payment` 阶段，不输出签名、密钥、session_key 或原始支付参数。
3. **旧订单检查挡住收银台**：再次购买前会查旧订单；查单接口失败时会停止，而非冒险重复创建可能已支付的订单。本次修复请求长度；没有绕过查单或直接发货。
4. **未创建的微信订单**：本地订单先保存，随后才拉起支付。微信 status=0 且其他字段为空/默认时，现在保持待支付，不误判为已支付订单的环境错误。不会据此发放权益，也不复用旧单号。
5. **恢复购买静默吞掉失败**：原先 Promise.allSettled 忽略所有查单错误，可能把服务失败显示为没有购买。现在未开通账户会显示真实恢复失败；已确认的会员权益仍保留。
