# 2026-10-29 真机图片与台球清晰度

## 已确认的原因

手机截图缺失的主背景、Logo、列表图标、主按钮和台球横幅，均使用上一轮生成的本地WebP。当前开发者工具自带的上传扩展名白名单 `js/e8278035f861568d39bfdd8777653eee.json` 不包含 `.webp`；模拟器从工作目录读图，手机使用上传包，两者不等价。

进一步检查当前用户配置中的上次 `pkgSize` 打包清单：其中有96条PNG引用、0条WebP引用；`main_bg.webp`、`home_logo.webp`、`primary_button_bg.webp`、`party_banner_empty.webp` 均不存在。上次实际包主包仅526,843 B，而目录内包含这些WebP的主包约1.85 MB。由此确认图片在上传前被过滤，而非凭手机截图推断解码能力。脱敏摘要存于 `/tmp/wx-decide-20261029-evidence/previous-package-summary.json`。

台球HUD原来以逻辑尺寸绘制离屏2D图，再放大到高分屏；主WebGL像素比还被限制为2。材质导入也统一限制到256px。这些都是本地代码可确认的清晰度损失来源。截图中桌框和球袋缺失则属于另一项模型渲染异常，不能仅以提高纹理分辨率解释。

## 修改

- 原图导入脚本统一输出PNG/JPEG并删除旧WebP；全部运行引用同步修改，含硬币动态图片、台球入场帧和鲨鱼动态背景。实际编码与后缀一致。
- Logo、中心图、主按钮和结果背景保留真彩PNG；横幅与聚会主按钮使用感知调色板PNG，其他插图保留透明通道。背景使用JPEG。已目视检查主按钮、横幅、结果背景，避免直接使用粗调色板压缩导致的大块色带。
- 工具依赖列于 `tools/requirements-assets.txt`，真值仍为只读Flutter资源；没有把旧WebP简单改名或继续有损转码成PNG。
- HUD画布、读取像素、GPU纹理统一按设备像素比绘制，触摸区域保持逻辑坐标；主WebGL使用设备实际像素比（不再固定限制为3倍），并受GPU最大纹理尺寸约束。
- 桌框木纹、桌框法线、球房和物件材质上限提高至512px；其他原始小纹理保持原尺寸。核心bundle改为同样的ES2018压缩构建，给材质留出包体空间，不改玩法。
- 原球房的顶点、法线、UV与索引改为独立、零偏移的TypedArray后上传，消除原生桥接忽略共享缓冲偏移时的风险。几何数值保持不变。材质编译错误也会记入本机台球诊断。

模型缓冲兼容处理已通过受限宿主测试，但尚未证实它就是该手机桌框缺失的最终根因；必须用新包在手机复核。

## 同日再复核：手机日志确认GLSL扩展声明顺序错误

用户10:05真机日志给出明确错误：`Extension directives must occur before any non-preprocessor tokens`，随后`dFdx/dFdy requires extension GL_OES_standard_derivatives to be enabled`。Frame/Pocket/TableInner均`ready:false, active:true`，DPR3.5，Canvas/drawingBuffer3168×1440；基础回退材质同样编译失败。这证实本次缺框由材质着色器编译失败导致，先前缓冲及回退处理没有解决它。

追到本机实际Babylon 8.56.2源码：`Shaders/default.fragment.js`在`__decl__defaultFragment`（uniform声明）之后声明导数扩展，`Engines/Processors/shaderProcessor.js`又在前面补入precision。桌面ANGLE接受了这一顺序，手机编译器拒绝。抓取旧bundle实际提交的shader也复现同样顺序：precision在第51行，uniform随后，扩展在第63行，与手机报错行号一致。

修改真值源`billiards/src/platform.ts`，在原生`shaderSource`提交前把扩展声明移到代码序言，保留`#version`优先、扩展顺序、原shader计算、纹理和光照，不修改第三方node_modules或简化原模型。由build.cjs重新生成core.js/renderer.js。该变换针对Babylon已经解析材质条件的最终GLSL源码，忽略注释中的假指令。
