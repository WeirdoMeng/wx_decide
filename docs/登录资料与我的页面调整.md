# 登录资料与“我的”页面调整

按用户要求：登录时通过微信头像昵称填写能力完善资料；“我的”展示头像、昵称、会员状态，隐藏账户编码与技术报错区。沿用原浅色玻璃卡片、蓝紫操作按钮；昵称下方采用灰色非会员徽章或金色会员徽章，图标原样使用用户提供的 `/Users/apple/Desktop/vip_member_logo.png`，复制到 `miniprogram/assets/original/vip_member_logo.png`，使用 aspectFit 避免拉伸。

## 用户流程

- 首次登录：点击圆形头像 → 微信原生选择头像；昵称输入框可选择微信昵称 → 点击“微信登录并继续”。头像和昵称由用户主动选择/确认，不通过已调整的 getUserProfile 静默获取。
- 有已保存资料的账户重新登录直接进入；旧账户缺少资料时停留在登录页补充，不影响原账户会员归属。
- 使用 form submit 获取当前昵称，避免昵称安全检测清空后误用缓存旧值。
- “我的”：圆形用户头像、昵称、省略超长内容；昵称下方显示灰色皇冠“非会员”或金色皇冠“终身会员”。支付/退款后继续使用服务端确认的免广告权益更新状态。
- 退出登录紧接联系客服，沿用同样的菜单行样式；套餐卡片顶部不显示已开通/未开通状态行。
- 所有环境均隐藏页面顶部的“沙盒测试”提示；内部支付环境选择和测试权益隔离保持原逻辑。
- 取消显示账户编码。内部账户 ID 仍用于订单归属、缓存隔离等原业务，不做数据删除。
- 登录和会员页不再渲染原始错误、错误码或堆栈。资料操作失败仅给简短操作反馈；支付/恢复使用“结果待确认”等用户提示。开发诊断保留在 Console。

## 资料持久化

- 新增当前账户的 updateProfile 云函数 action，不接收客户端指定的账户或会员身份。
- 头像经客户端文件读取传入云函数，由服务端校验 PNG/JPEG、体积不超过512KiB，上传到云存储。
- 云数据库原用户记录增加 nickname、avatarFileId、profileVersion；事务仅更新资料字段，保留最新会员、退款和订单字段。
- 原/沙盒用户集合继续隔离，头像路径也包含支付环境与当前账户目录。无需新建集合或索引。
- 服务端获取头像临时地址，不要求放宽客户端云存储读写权限；图片获取失败不阻断会员查单。
- 更新头像后清理旧文件；资料事务失败时清理本次新文件。
- 前端分别比较资料版本和会员权益版本，避免迟到的资料回复回退会员或退款状态。

## 涉及文件

`pages/login`、`pages/mine`、`utils/account.js`、`cloudfunctions/membership/index.js` 与 `lib/service.js`。沙盒函数由 `node tools/build-membership-sandbox.cjs` 重新生成，保持单一业务真值源。`project.config.json` 基础库由2.20.1调整为2.24.4，满足头像昵称能力（2.21.2+）及组件内容检测（2.24.4+）的开发者工具预览要求，未调整其他SDK依赖。

官方依据：[头像昵称填写](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile.html)、[image 云文件支持](https://developers.weixin.qq.com/miniprogram/dev/component/image.html)。

## 验证与更新

- 138 项 Node 测试通过：资料持久化、账户绑定、非法输入拒绝、文件清理、会员字段保留、异步版本合并、表单值与资料完整登录流程，以及既有支付/沙盒/广告/玩法回归。
- 17 个 WXML、18 个 WXSS 由微信原生编译器编译通过；业务与云函数 JS 语法检查通过；沙盒生成结果一致性检查通过。
- 主包输入 2,071,773 字节，低于 2 MiB；实际上传体积以开发者工具为准。
- 当前打开的工具停在云开发控制台，未用真实头像执行上传，也未完成微信模拟器/Android/iOS 的本轮头像昵称和视觉验收。以上编译/测试不能替代真机结果。

本次包含新的云端资料保存方法。使用新页面前，须更新上传两个函数 `membership` 与 `membership_sandbox`，选择“上传并部署：云端安装依赖”，再重新编译并生成手机预览。密钥和已有会员数据保持原配置，不需要重建数据库。若开发工具仍停留旧基础库，重新打开项目后确认2.24.4或使用支持相同能力的版本。
