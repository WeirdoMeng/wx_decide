# 沙盒支付测试：照着操作

已完成本地代码，尚未替你上传部署或完成沙盒付款。继续使用现有云环境 `cloud1-d2gxqceib97d64cb4`，不用再创建一个云环境。

## 1. 上传两个云函数

微信开发者工具左侧 `cloudfunctions` 下，现在有：

- `membership`：正式支付及统一通知入口，现网 Key 保持原值。
- `membership_sandbox`：沙盒支付，仅使用沙盒 Key。

**两个目录都右键 → 上传并部署：云端安装依赖**。原函数这次也要更新，才能转发沙盒通知。不要删除原函数，不需要重建正式集合。

`membership_sandbox` 是由 `node tools/build-membership-sandbox.cjs` 生成的部署目录；业务逻辑的真值源为 `membership`，不要单独手工修改生成目录。更新源后重新生成；`--check` 可检查一致性。

## 2. 仅配置新函数 membership_sandbox 的环境变量

云开发控制台 → 云函数 → `membership_sandbox` → 配置 → 环境变量。

| 名称 | 值 |
| --- | --- |
| `WX_APP_SECRET` | 与原 membership 相同的小程序 AppSecret |
| `VIRTUAL_SANDBOX_APP_KEY` | 虚拟支付后台的沙盒 AppKey |
| `WX_APP_ID` | `wx9caeac69341808c8`（代码已有默认值） |
| `VIRTUAL_OFFER_ID` | `1450698692`（代码已有默认值） |
| `VIRTUAL_PRODUCT_ID` | `1000001`（代码默认值；核对该道具在沙盒可用，若不同填沙盒实际道具 ID） |

保存并应用配置。沙盒商品单价同样核对为 990 分。**不要把原 membership 的 VIRTUAL_APP_KEY 换成沙盒 Key**。不要将两个密钥贴到聊天或小程序代码中。

支付环境由两个函数各自的代码固定为 0 和 1，不接受客户端传入环境切换，也不需要新增 VIRTUAL_PAY_ENV 环境变量。

## 3. 创建三个测试集合

云开发 → 数据库 → 新建集合，名称逐个复制：

```text
sandbox_member_users
sandbox_member_orders
sandbox_member_grants
```

每个集合均选择自定义安全规则：

```json
{"read": false, "write": false}
```

为 `sandbox_member_orders` 建两个组合索引：

| 索引名 | 字段 1 | 字段 2 |
| --- | --- | --- |
| owner_created | openid 升序 | createdAt 降序 |
| state_checked | state 升序 | checkedAt 升序 |

等索引构建完成。规则/索引参考文件位于 `cloudfunctions/membership_sandbox/database.*.json`，文件本身不会自动创建数据库配置。

## 4. 保留原通知配置

原先云开发消息推送仍指向 `membership`，不要改成只发给 `membership_sandbox`。

更新后的 `membership` 会按通知 `Env=1` 或新沙盒业务单号 `S` 开头转发给 `membership_sandbox`。退款事件没有 Env 时也可按商户单号分流。正式订单继续由原函数处理。转发后的订单必须通过微信查单及所属环境验证后才发放权益。

检查两个函数各自的 `reconcileOrders` 定时触发器均已部署，配置为每 5 分钟补偿一次。

## 5. Android 真机预览测试

重新编译，再生成手机预览二维码，用 Android 手机打开。

1. 登录，进入“我的”，应看到 **“沙盒测试 · 会员权益仅在测试版本生效”**。
2. 测试取消付款，确认没有开通免广告。
3. 主动完成一次沙盒购买，核对查单/推送成功、测试会员免广告生效。
4. 退出再打开，点击恢复购买，验证测试权益仍可恢复。
5. 核对 `sandbox_member_orders` 状态和 `sandbox_member_grants`，正式集合不应新增本次沙盒单。沙盒单号以 `S` 开头；正式新单以 `T` 开头。
6. 测试重复通知、付款后立即退出、网络恢复、退款后回收；都必须以微信实际结果为准，不能手工改 adFree 代替验证。

先前的正式会员不会自动成为沙盒会员；沙盒购买也不会开通正式会员。沙盒与正式的设备待确认订单缓存同样隔离。

**Apple 支付不支持沙盒**，当前开发版/体验版在 iPhone 会明确提示改用 Android，不会自动退回现网付款。正式版仍按原现网流程运行。

## 版本选择与验收边界

| 小程序版本 | 云函数 | 请求 env | 数据集合 |
| --- | --- | --- | --- |
| develop：开发/预览 | membership_sandbox | 1 | sandbox_member_* |
| trial：体验版 | membership_sandbox | 1 | sandbox_member_* |
| release：正式发布版 | membership | 0 | member_* |

无法识别版本时停止登录，不默认为现网付费。客户端还会核对服务器返回的环境及实际付款 signData.env，拒绝不匹配的响应。

微信 API 的请求 env 为 0/1，查单响应 env_type 为 1=现网、2=沙盒，两者不可混用。通知 Env 同样必须与接收函数匹配。

依据：[虚拟支付官方说明](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)、[客户端 API](https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestVirtualPayment.html)、[query_order](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_query_order.html)。个人接入 Skill 的默认现网说明仍用于正式部署；本次是独立的测试环境扩展。

本地验证：132 项 Node 测试通过，包括两个环境的请求参数/密钥使用、数据集合路由、签名、沙盒发货和退款、通知转发、不回退现网、版本识别、缓存隔离及生成文件一致性；业务和云函数 JS 语法及原生 WXML/WXSS 编译另行记录。沙盒实际付款、通知、退款尚未取得手机验收证据。正式支付也仍需一笔真实付款→通知→权益→账单的一致性验收；用户确认现网 Key 修正后可用，不等同于所有环节已核验。

## 支付成功后出现 WECHAT_268490002

该错误为微信请求参数错误，必须看脱敏 errmsg，不能仅由外层 action=query 判断具体接口。query 会先查单，之后可能确认发货。已修改确认发货为按微信接口定义只传二选一单号，优先使用真实查单得到的 wx_order_id，不再传未定义 env；有效发货推送查单提交权益后直接成功应答，不额外调确认发货接口。查单补发时确认接口失败保留 delivered_pending_ack 和错误码并重试，但返回已确认的权益。真正的查单失败仍不会发货。

更新后需重新部署 membership、membership_sandbox，然后在已有预览中点击恢复购买；不重复付款。如果仍有参数错误，提供带“订单查询/发货确认”和脱敏原因的错误文字，不提供 payCompletedData、openid、签名或密钥。本轮尚未读取到真实微信 errmsg，也未独立证明此次错误一定来自确认发货接口。

### 只看到 action/code 时如何取完整原因

已增加可复制的单行 `[account] cloud-result` 诊断，包含 functionName、payEnv、version、stage 和脱敏 message。当前云端诊断版本为 `query-detail-20261029`。部署两个函数并重新编译/生成预览后，点击恢复购买即可取诊断，无需重新付款。version=未提供 表示云端没有返回新诊断版本；仍是仅 action/code 的对象日志表示前端仍未采用新日志格式。错误码本身不能确认被拒绝的参数，本轮并未宣称已修复未知字段问题。
